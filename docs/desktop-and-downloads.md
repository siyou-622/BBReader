# 桌面应用与可选择下载

## 改造内容

在原 0.3.1 Chrome 扩展上新增 Electron 桌面应用，继续加载同一份 `extension/index.html`、UI、解析器和业务后台。原扩展与独立页面预览继续可用。修改前清单、影响范围见 [change-plan.md](change-plan.md)。

课件页增加课程内单选/多选、勾选当前筛选结果、下载已勾选、下载该课程全部课件、元数据读取、批次进度和失败项重试。原自动归档与“重试未完成的文件”入口保留。

## 安装与启动

| 系统 | 包格式 | 启动方式 | 运行要求 |
| --- | --- | --- | --- |
| Windows | `*-setup.exe` NSIS 当前用户安装包；`*-portable.exe` 便携版 | 开始菜单/桌面快捷方式；或双击便携 EXE | Windows 10/11，匹配 x64 或 arm64 包 |
| macOS | `.dmg`、`.zip` 内含 `BBReader.app` | 将 App 拖入 Applications 后启动，或解压 ZIP 启动 | macOS 13 Ventura 及以上，匹配 Intel/Apple Silicon 包 |
| Linux | `.AppImage`、`.deb` | AppImage 授予执行权限后运行；Deb 安装后从应用菜单打开 | Electron/Chromium 仍支持的桌面发行版，GTK/NSS 等系统库；AppImage 可能需要系统 FUSE |

Electron 自带 Chromium 与 Node 运行时，最终用户无需安装 Chrome、Node、Python、Rust 或本地 Web 服务。基础版无需管理员权限（Linux Deb 安装属于系统包管理操作）。首次在应用内点击“前往学校登录”，完成学校认证后“立即检查”；应用不会读取 Chrome 的 Cookie 或凭据数据库。

本地未配置签名证书，生成的安装包没有开发者签名/Apple 公证。正式分发应配置 Windows 代码签名及 macOS Developer ID/公证；macOS/Linux 的包需要在对应系统构建和实机验收，不能把 Windows 测试等同于三平台验收。平台要求依据 [Electron 平台支持](https://github.com/electron/electron/blob/main/README.md#platform-support)；包格式与构建边界见 [electron-builder 多平台构建](https://www.electron.build/docs/features/multi-platform-build/)。

## 通信和持久化

- 桌面本地页面通过 `bbreader://app` 读取随包文件，没有 HTTP 监听端口，也没有独立服务器。
- 隐藏业务窗口运行原后台；安全 preload 和 IPC 适配存储、定时器、学校窗口脚本、下载与本地助手。远程学校页面无 Node 和 IPC 桥，所有窗口启用隔离和沙箱。
- 学校窗口、页面读取、HEAD 与附件流式下载共用 `persist:bbreader` 会话。读取接口沿用原只读 URL 白名单，同时允许原完整选课列表的严格验证入口，避免封装后漏读隐藏课程。
- 课程启动地址若直接返回菜单而没有重定向，解析器从经校验的 `type=Course&id=...` 恢复课程上下文；原 `course_id` 路径优先。
- macOS 继续使用原助手的长度前缀 JSON stdio 协议和固定扩展标识，只调用用户目录中两个 BBReader 专用 App 的固定二进制，不执行 shell。先按原说明安装助手，再在应用内允许“macOS 系统集成”。原助手的钥匙串、目录、SHA-256 与 Reminders 配置沿用，Swift 源码未改。
- 桌面索引、队列、下载历史、权限保存在 Electron `userData/desktop-state.json`；Cookie、IndexedDB 和主题位于同一应用目录的会话配置。Windows 通常为 `%APPDATA%/BBReader` 或 `%APPDATA%/bbreader`，Mac 为用户 `Library/Application Support`，Linux 为用户配置目录；实际目录由 Electron `app.getPath('userData')` 决定。
- 扩展和桌面使用独立索引、Cookie、AES 密钥和主题；不自动迁移或清除扩展数据。初次桌面登录需要重新扫描，已有文件不会覆盖。若两端共用下载目录，首次桌面下载可能保留新的同名副本；macOS 助手内容去重继续有效。
- Windows/Linux 关闭主窗口会退出应用；macOS 关闭窗口后应用可继续检查，菜单“退出”才停止。休眠或退出时不执行定时任务，恢复或重启按校园时间补查；没有新增开机自启动或系统计划任务。

## 可选择下载的使用与范围

1. 保持默认开启的“检查后自动下载全部课件”，可继续原自动归档方式。希望只下载部分时，在第一次检查前关闭该开关；扫描仅建立课程、作业和课件索引。
2. “课件归档”按已启用课程分组，显示名称、类型、大小、下载状态或错误；服务器未提供或尚未读取的大小显示“大小未知”。点击“读取类型与大小”对该课程的全部课件发出 HEAD 请求，不下载正文；不支持 HEAD 的服务器仍可正常下载，完成后更新实际大小。
3. 勾选一个或多个课件，再点击该课程的“下载已勾选”。勾选在切换搜索时保留，按钮数量包含被搜索隐藏的勾选项；每次提交只处理这一门课程。
4. “勾选当前筛选结果”只勾选该组可见项。“下载该课程全部课件”处理这一门课程全部已识别索引项，忽略搜索和新增/更新筛选条件，排除其他课程；保留的旧记录会标注“此次未确认”，失效地址按失败报告。
5. 批次显示完成数/总数、成功、跳过、失败，以及当前文件已收到字节/总字节。总大小未知时显示已收到字节，避免虚假的百分比。
6. 点击“重试本批次失败课件”只重试失败项。原“重试未完成的文件”在活动批次中继续当前队列；批次结束后恢复原已启用课程、最近扫描文件范围的核对/重试，不重新扫描课程。该旧入口是显式下载请求，即使自动下载开关关闭也会执行。

## 新课件与更新提醒

每次完成检查，在各页面顶部显示“新增 N 份”“更新 N 份”。点击进入对应课件筛选；列表标注“新增”或“有更新”，可返回全部课件，勾选在切换筛选时保留。“下载该课程全部课件”仍覆盖该课程全部已识别课件，不受新增/更新筛选影响。

- 首次扫描显示“首次收录 N 份”，建立基线；升级后的已有索引不会被全部算成新增。新加入的课程首次发现的文件属于新增。
- 使用课程 ID + 附件 ID 区分课件；同一课件在课程多个位置重复出现只统计一次。不同附件 ID 即使同名也属于不同课件。
- 每次检查通过同一学校会话发送附件 HEAD，请求 ETag、Last-Modified 和 Content-Length。优先比较共同 ETag，否则比较修改时间或明显的大小变化；大小相同且无版本标记不能证明未更新，会显示“未能核对更新”。学校更换附件 ID 视为新增。
- 版本信息不足时建立/保留可用基线，不凭空认定更新。HEAD 不支持或部分页面失败时，显示未核对数量或统计可能不完整；原下载仍可使用。所有版本标记都缺失时无法可靠识别等大小更新，不会为检测下载正文。
- 报告保留至下一次完成检查；检查中展示上次结果。检查中断不会发布虚假的零结果，版本基线在检查完成后才提交，恢复后仍可识别中断前发现的新增课件。报告、检测基线独立于下载记录，不改变下载去重、文件名和保存位置。

## 设置预览软件

在“连接与设置 → 课件预览方式”选择：

1. **优先在 BBReader 内预览**（默认）：继续本地/在线 PDF、图片和文本预览；已下载的其他支持文档使用系统软件打开。
2. **使用系统默认软件打开**：使用操作系统的文件关联，例如默认 PDF 阅读器。
3. **使用指定软件打开**：通过“选择软件…”选 Windows `.exe`、macOS `.app` 或 Linux 可执行程序。指定软件需支持以文件路径参数打开文档，可随时重选。

外部方式要求课件已下载且文件存在；未下载时提示先下载，点击“预览”不会自动下载。软件或文件已移动、系统无关联软件时给出明确反馈。仅支持文档、PDF、图片和文本等预览类型；不通过此入口执行附件程序。选择结果保存在桌面配置中，重启有效。扩展沿用浏览器预览入口，隐藏桌面软件设置。

此轮无需新增依赖、管理员权限或网络服务；指定阅读软件需要用户自行安装，应用内预览是无需额外软件的替代方式。打开指定软件使用独立参数而非 shell 命令，网页不能直接指定本地软件/文件路径。

## 文件兼容和异常处理

| 情况 | 行为 |
| --- | --- |
| 重复点击、重复 key | 单批次 key 去重；检查、下载或活动批次期间拒绝第二个批次，避免队列覆盖 |
| 已保存且未变化 | 沿用 ETag/Last-Modified、相对路径与真实存在性核对；记为“跳过”；无可靠版本信息时重新下载 |
| 文件同名 | 扩展继续 Chrome `uniquify`；桌面在目标目录独占预留空闲文件名，以 ` (1)`、` (2)` 保留副本；不覆盖旧文件 |
| 命名和目录 | 仍由 `attachmentName` / `cleanName` / `browserFilename` 决定服务器名、扩展名、学期/课程/内容层级和 Windows 相对路径缩短；单/多附件规则不变 |
| 保存位置 | 桌面默认系统下载目录下 `BBReader/学期/课程/内容目录`；菜单“选择下载目录…”改变之后的新下载，旧文件不会移动。macOS 集成仍先写 `BBReader-staging` 再交给助手归档 |
| 网络中断、超时、取消 | 单项失败并记录错误，继续其他项，结束后可重试；桌面连接等待 20 秒、读取空闲等待 60 秒，中断的当前写入文件会清理 |
| 应用关闭或崩溃 | 索引和批次逐项持久化；重启将未完成桌面下载标为中断，原核对器消费该记录并继续队列；失败项重试从头下载，不宣称 HTTP 断点续传。突然终止时残留的未完成文件不会作为成功归档，可能需用户清理 |
| 学校登录页、空文件、不允许的来源 | 保留失败反馈，不记录为成功课件；主进程限制附件来源、保存路径及符号链接，助手继续原格式/校验和验证 |
| macOS 助手缺失/未选根目录 | 批次各未处理项标为失败，允许安装助手、选择目录或切换模式后重试，不永久锁住设置 |

批次结束后保持结果可查看，不会因为后续恢复定时器而悄悄下载未勾选项。新课程检查或原继续入口会恢复它们各自的原范围。清空索引仍保留已下载文件；桌面卸载默认保留应用数据，需用户自行删除本地配置目录。

## 依赖、配置和权限

| 新增项 | 必要性 | 替代方案 |
| --- | --- | --- |
| Electron 44、electron-builder 26（锁文件固定实际依赖） | 提供跨平台窗口、Chromium 会话和安装包；仅开发时 npm 依赖，生产包内嵌运行时 | 继续原 Chrome 扩展无需这些依赖；Tauri 需要重新适配浏览器 API、平台 WebView/认证和系统后端，不能直接复用扩展环境 |
| Playwright（开发依赖） | 启动真实 Electron，验证页面、IPC、扫描、下载、导出及持久化；不进入最终安装包 | 手动实机验证；Node 单元测试仍无需 npm 安装 |
| `autoDownload`（默认 true） | 保持原行为，同时提供只扫描再选择的工作流 | 保持默认自动归档 |
| `downloadBatch` / `downloadRequested` / 文件 `metadata` | 可恢复的课程批次、原继续入口的一次显式范围、类型和大小 | 原字段全部保留，旧索引无需迁移 |
| 下载目录和应用数据写入 | 本地归档、索引与队列 | 用户菜单选择有写权限的下载目录；无管理员权限要求 |
| CAS 访问授权（按需确认） | 保存账号后自动填写学校认证表单 | 不保存账号，在应用内手动登录 |
| macOS 助手通信授权、系统 Reminders/文件权限（可选） | 钥匙串、自定义课程目录、SHA-256 和提醒事项 | 使用桌面独立模式；Windows/Linux 隐藏这些功能 |

调试隔离配置可用 `--bbreader-profile=绝对路径`、`--bbreader-downloads=绝对路径`。测试脚本使用仓库 `verification/` 中独立目录，不接触真实学校账号或用户归档。

## 软件更新与学校登录反馈

桌面 0.3.2 新增软件更新窗口，已连接 GitHub `siyou-622/BBReader` 的 Releases，使用方式与后续发布步骤见 [desktop-updates.md](desktop-updates.md)。新增 electron-updater 运行依赖随包提供；真实跨版本覆盖安装仍需隔离环境验收。

学校登录窗口在加载初期保留“加载中”状态，防止空网址导致 Invalid URL；网络/代理/证书失败或长时间未加载会显示错误与重试入口。原学校 Cookie 保留，不清除登录状态、不改代理或关闭证书验证。真实空白配置已验证可打开统一认证页；用户原会话的具体白屏原因仍需在该环境确认。Windows 索引原子保存增加短暂文件锁重试，避免导出或队列保存因瞬时占用失败。

## 构建与回归

2026-10-09 界面调整：课程选择相同也可再次保存；保存期间和后台检查/下载期间锁定按钮。课件行不展示完整路径，文字明确区分已下载、未下载、下载中、失败及文件已移动/删除。原索引路径保留，桌面定位操作只接受课件 key，文件存在才打开所在文件夹；缺失文件可按原规则重新下载。

“预览”与下载按钮分开，操作按钮横向排列；窄屏时整体移至文件名下方。PDF、PNG/JPEG/GIF/WebP、TXT 在独立桌面窗口预览：已有文件优先读取本地，未下载文件使用同一学校登录会话读取并强制内联显示，不新增归档下载记录或落盘文件。学校返回登录页/不支持格式时显示说明；预览窗口无 Node 和本地 IPC。已下载的 Word、PowerPoint、Excel、OpenDocument、RTF、CSV、EPUB 使用系统关联应用打开，需本机有对应查看软件；可执行文件等类型不会通过预览按钮启动。Chrome 扩展将原网页入口显示为“预览”，浏览器模式可用原 downloads 权限定位文件。

按本轮要求，课件列表隐藏上传时间。既有上传时间解析与索引字段保留；可用的 HTTP Last-Modified 仍显示为“文件更新时间”，不将其当作老师上传时间，也不使用下载完成时间或作业截止日期替代。

桌面图标采用用户提供的蓝色文档勾选样式，源文件 `desktop/icons/icon.svg`，已生成 PNG/ICO/ICNS 并配置窗口、Windows 可执行文件/安装快捷方式、macOS 和 Linux 打包。修改图标后可用 `node scripts/build-icons.cjs` 重新生成（复用现有开发依赖，无新增用户依赖）。原 Chrome 扩展图标保留。

预览没有新增运行依赖或用户授权项。PDF 仅在无 preload、无 Node 的预览窗口启用内置查看器；自定义协议按 [Electron 官方协议配置](https://www.electronjs.org/docs/latest/api/structures/custom-scheme) 允许内置扩展工作，不安装第三方浏览器扩展。学校原文件不会作为网页脚本执行；返回 HTML 时显示登录提示。可继续使用系统关联软件作为本地课件预览的替代方式。

```sh
npm ci
# 若包管理器禁止依赖安装脚本，需要显式完成 Electron 运行时下载：
node node_modules/electron/install.js
npm test
npm run desktop
npm run desktop:smoke
npm run desktop:pack   # 当前平台解包目录
npm run desktop:dist   # 当前平台安装包
python scripts/build.py --browser-only  # 原扩展包，Windows 也支持 UTF-8
```

按目标平台构建：Windows `npm run desktop:dist -- --win --x64`；Mac `--mac --arm64` 或 `--mac --x64`；Linux `--linux --x64` 或 `--linux --arm64`。输出 `dist/desktop/`。三系统 GitHub Actions 可手动触发或推送 `v*` / 历史 `desktop-v*` 标签；构建产物不会自动公开发布，正式更新使用标准 `v*` Release 标签。跨系统构建、签名与公证限制按 electron-builder 官方说明处理。

回归记录和待实机验证清单见 [regression.md](regression.md)。
